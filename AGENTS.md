# Правила работы с Career Quest

- Рабочая ветка для изменений пользователя `mynameisayko` — `ayko`. Готовьте изменения там перед переносом в `main`.
- Публикацию в `main` выполняйте по запросу пользователя. Не используйте force-push и не переписывайте опубликованную историю без явного запроса.
- **Перед каждым push, обновляющим `main`, обязательно актуализируйте корневой `README.md`.** Обновляйте соответствующие разделы по фактическому поведению кода: возможности, запуск, переменные окружения, API, данные, ограничения. Добавляйте запись в «Журнал обновлений main» с изменениями и реально выполненными проверками. Одна новая дата без описания изменений недостаточна.
- Получайте актуальную `origin/main` перед объединением, сохраняйте изменения других участников. После переноса возвращайтесь на `ayko` для дальнейшей работы.
- Выполняйте релевантные проверки перед публикацией; для backend текущая команда: `PYTHONPATH=backend python -m unittest discover -s backend/tests -v` (на Windows задайте `$env:PYTHONPATH = "backend"` и используйте `.\.venv\Scripts\python.exe`). Не используйте рабочую SQLite-базу для тестовых выполнений или импортов.
- Проверяйте автора коммита и реальную Git-авторизацию отдельно: `user.name` не меняет аккаунт, выполняющий push. Для работы этого пользователя ожидается `mynameisayko`; настройки делайте локальными для репозитория. Не печатайте ключи/токены.
- Не добавляйте API-ключи, HR-пароли, `.venv`, кеши и рабочую SQLite-базу в Git.
- Соблюдайте единый расчёт `recommendation_candidates()` для профиля, рекомендаций и HR. Контрольные показатели HR проверяются на исходном датасете и пустой базе completions.
- Различайте проверенный локальный расчёт и реальный вызов OpenAI: успешные unit-тесты не подтверждают доступность API-модели, ключа или баланса.
- `.githooks/pre-push` требует изменения README при обновлении `main`. Для нового клона его можно включить через `git config --local core.hooksPath .githooks`. При существующих пользовательских hooks сначала сохраните их поведение. Не обходите проверку при обычной публикации.
