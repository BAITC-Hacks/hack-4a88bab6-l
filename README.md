# Career Quest

Career Quest — демонстрационное веб-приложение для выбора добровольного шага профессионального развития. Сотрудник видит цель, навыки и участие, получает 1–3 объяснимые рекомендации и может выбрать, выполнить или пропустить шаг. HR видит профиль выбранного сотрудника, разрывы компетенций, доступность шагов и участие. Решение о развитии остаётся за человеком.

## Источники и границы

- Требования: `references/career_quest_requirements.pdf`, страницы 2–4. Общие принципы содержательного AI: страница 4 `references/voice_router_with_shared_requirements.pdf`. Эти файлы находятся в выданном `career_quest_codex_pack.zip`.
- Данные: `career_quest_dataset.zip` с каталогом `case_1/career_quest_dataset/`: `employees.json`, `skills.json`, `events.json`, `activity_history.csv` и README на трёх языках.
- Wireframe в `references/` — ориентиры композиции. Нарисованные курсы, оси и числа не входят в каталог.
- Skip, архив HR, выбор цели и показатель покрытия — решения MVP, описанные в [docs/ASSUMPTIONS.md](docs/ASSUMPTIONS.md).

Исходный набор содержит 200 сотрудников, 40 мероприятий, 60 навыков, 32 профиля роли/грейда и 2 743 записи участия. Это контрольные числа первого импорта, а не пределы приложения. Данные синтетические; материалы организаторов не предназначены для публичной публикации.

## Запуск одной командой

Нужны Docker и Docker Compose. Поместите выданный `career_quest_dataset.zip` в корень репозитория рядом с `compose.yaml`. Если у вас только `career_quest_codex_pack.zip`, извлеките из него ровно `career_quest_dataset.zip`, не переименовывая внутренний архив.

Создайте приватный `.env` из шаблона (`cp .env.example .env` в Linux/macOS):

```powershell
Copy-Item .env.example .env
```

Задайте в `.env` непустой `DEMO_PASSWORD`. Для реального AI-подбора добавьте `OPENAI_API_KEY` **только в серверный `.env`** самостоятельно. Пустой ключ включает явно помеченный резервный подбор. Ключ нельзя помещать в `VITE_*`, браузер или исходный код.

```powershell
docker compose up --build
```

Откройте `http://localhost:8000` или порт `APP_PORT` из `.env`. Первый запуск импортирует стартовый набор в SQLite. База находится в именованном томе `career_quest_data`; повторный запуск не должен сбрасывать действия или начислять навыки повторно. ZIP подключён к контейнеру только для чтения. Наличие Docker на конкретном компьютере проверяется отдельно.

| Переменная | Значение | Назначение |
|---|---|---|
| `DEMO_MODE` | `true` | Синтетические аккаунты и явно помеченное моделирование будущих сессий. |
| `DEMO_PASSWORD` | задаётся в `.env` | Общий пароль демо-аккаунтов; сервер хранит хеш. |
| `OPENAI_API_KEY` | пусто в шаблоне | Секрет серверного вызова OpenAI; без него показывается fallback. |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель Responses API. |
| `COOKIE_SECURE` | `false` для локального HTTP | Принудительно включает Secure-cookie при HTTPS за proxy. |
| `APP_PORT` | `8000` | Порт хоста в Docker Compose. |
| `DB_PATH` | `/data/career_quest.sqlite` в Compose | Постоянная база SQLite. |
| `DATASET_ZIP` | `/app/career_quest_dataset.zip` в Compose | Исходный архив внутри контейнера. |

`.env`, `.env.txt`, база и исходные архивы исключены из Git и Docker build context. Не делайте публичный push/deploy с материалами хакатона.

При размещении за HTTPS reverse proxy выставьте `COOKIE_SECURE=true` и настройте список доверенных IP для forwarded headers в инфраструктуре. Настройки по умолчанию рассчитаны на локальный HTTP-демо.

### Локальная разработка

Нужны Python 3.12 и Node.js 22. Из корня проекта установите зависимости и запустите API:

```powershell
Copy-Item .env.example .env
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.app.main:app --reload --port 8000
```

В другом терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Backend читает `.env` из корня проекта. При запуске вне Compose задайте в нём абсолютные локальные пути `DB_PATH` и `DATASET_ZIP`; Vite передаёт `/api` на `http://127.0.0.1:8000`. В Docker Compose пути выставлены автоматически.

## Вход и экраны

В `DEMO_MODE=true` используются синтетические учётные записи приложения, которых нет в исходном датасете: `hr@careerquest.test` и `e0005@careerquest.test`. У каждого исходного и нового импортированного профиля автоматически появляется демо-логин вида `e0005@careerquest.test`. Пароль — значение `DEMO_PASSWORD`; его изменение при перезапуске обновляет хеши демо-аккаунтов и аннулирует их действующие сессии. При `DEMO_MODE=false` вход в демо-аккаунты закрыт. Должностная `role` в JSON не выдаёт права HR; сервер хранит роль доступа отдельно, проверяет владельца данных и использует HttpOnly-cookie для сессии.

| Маршрут | Содержимое |
|---|---|
| `/login` | Вход без регистрации и восстановления пароля. |
| `/employee` | Профиль, цель и её происхождение, текущие и требуемые навыки, расчётная динамика, история и рекомендации. |
| `/hr/employees` | Поиск и фильтры сотрудников, профиль выбранного человека, архивирование и восстановление предложения с причиной. |
| `/hr/competencies` | Разрывы по индивидуальным целям, причины отсутствия шага, участие и модальное окно импорта. |

Пропуск рекомендации доброволен: он не уменьшает навык и не создаёт `no_show`/`declined`. Сотрудник может вернуть мероприятие в рассмотрение. Архив HR действует на пару сотрудник/мероприятие, сохраняет историю и причину, виден сотруднику и обратим; восстановление архива не отменяет Skip. HR не отмечает обучение выполненным от имени человека.

## От данных к рекомендации

```text
JSON/CSV → валидация и SQLite → replay завершений → цель и разрывы
         → допустимые мероприятия → OpenAI выбирает 1–3 шага
         → серверная проверка ответа → UI и сохранённые действия
```

`employees.skills` — неизменённая база последней оценки. Сервер применяет только `completed` после `last_review_date` до даты среза `2026-10-01`, затем новые завершения приложения ровно один раз. Исходная история до оценки остаётся видимой. Для каждого навыка события:

```text
new_level = max(current_level, min(5, current_level + gain, max_level))
actual_gain = new_level - current_level
```

Частичное прохождение не даёт частичный уровень. Отсутствующий навык равен 0. Выполнение обязательного мероприятия может повысить навык, хотя оно исключено из добровольных рекомендаций. Для self-paced исходный `date` — дата зачисления, а точного времени завершения CSV не содержит; для импортированного `completed` она используется как приближение.

Цель берётся из `career_goal` или отдельно подтверждённого выбора. При отсутствии цели до Lead показывается **предложение** следующего грейда текущей профессии; для Lead — развитие в текущем профиле без обещания пятого грейда. Для выбранного профиля:

```text
gap(skill) = max(0, required_level - current_level)
coverage_pct = 100 × Σ min(current_level, required_level) / Σ required_level
```

В знаменатель входят только положительные требования цели. При нулевом знаменателе процент не вычисляется. «Покрытие требований цели» не является вероятностью повышения; грейд автоматически не меняется.

Backend до вызова модели отсекает обязательные, недоступные по **текущей** роли/грейду, prerequisites и датам, уже завершённые неповторяемые, пропущенные сотрудником, архивированные HR и шаги без полезного прироста. `self_paced` доступен без сессии. Исключение на повтор — клуб `EV_036` при новой допустимой сессии и реальном приросте. Исторические `no_show`/`declined` не становятся пожизненным запретом.

OpenAI получает минимум контекста выбранного человека без имени, email и пароля, все допустимые альтернативы и пул проверяемых фактов. Модель ранжирует 1–3 шага и возвращает `event_id`, действие и `evidence_ids`; она не вычисляет уровни и не меняет SQLite. Backend проверяет IDs, факты и актуальность версии, затем формирует отображаемые числа. Источник `AI` или `fallback` и время расчёта должны быть видны. При отсутствии ключа, ошибке или таймауте показывается обозначенный резервный подбор по правилам. Автоматические тесты с mock не проверяют реальный доступ к API.

Текущий выбор и результаты ограниченных live-проверок моделей записаны в [docs/MODEL_SELECTION.md](docs/MODEL_SELECTION.md). Развёртывание в Compose использует один процесс Uvicorn. Блокировка одновременных AI-запросов для одного сотрудника хранится в памяти процесса; для запуска с несколькими workers нужна общая координация через БД или очередь.

## Импорт дополнительных профилей

HR открывает импорт на странице компетенций. Загрузите дополнительный `employees.json` в исходном формате `{meta, employees}` и, при наличии, `activity_history.csv` с исходными заголовками. Каталоги навыков/мероприятий повторно загружать не нужно. Сначала просмотрите preview с количеством новых записей, дублями и ошибками, затем подтвердите импорт. При обновлении базовой оценки тем же днём, когда человек завершил активность в приложении, preview предлагает явное подтверждение, что новая оценка уже включает эти завершения; без отметки они остаются в replay. Ссылки проверяются по объединению имеющейся и загружаемой базы; конфликт ID с другим содержимым должен быть явным. После успешной транзакции новые профили доступны в поиске HR, сводки пересчитаны. Файлы импорта не отправляются во внешние API для разбора.

## Проверки и пятиминутная демонстрация

Из корня репозитория:

```powershell
python -m pytest
cd frontend
npm run typecheck
npm run build
```

Статус фактически выполненных проверок указан в [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md). Live-вызов OpenAI требует собственного ключа и проводится отдельно.

Отдельная явная платная проверка реального AI без изменения состояния рекомендаций:

```powershell
.venv\Scripts\python.exe scripts/live_openai_check.py --employee E0005
```

Скрипт читает ключ только из серверного окружения/`.env` и выводит безопасный итог: модель, результат валидации, время и ID мероприятий. Команда не входит в `pytest` и делает оплачиваемый запрос к OpenAI.

1. Войти как `e0005@careerquest.test`; показать цель Senior, разрыв System Design и историю. У E0005 исходная история содержит три **завершения** Public Speaking Club, а не три пропуска.
2. Запросить AI-подбор, раскрыть три фактора и подтверждённый эффект. `EV_007` — допустимый пример, но не жёстко заданный ответ.
3. Пропустить добровольный шаг, получить альтернативу и при необходимости вернуть пропущенное.
4. Выбрать и завершить доступный шаг; для будущей сессии в демо-режиме использовать явную кнопку «Смоделировать выполнение». Показать изменение навыка и покрытия.
5. Войти как HR, найти E0005, увидеть обновление, архивировать предложение с причиной и восстановить его. Открыть сводку компетенций и preview дополнительного профиля/истории.

Приложение не проводит обучение внутри себя, не интегрировано с LMS/SSO и не служит системой оценки персонала. Ограничения исходных дат и расчётов указаны в [docs/ASSUMPTIONS.md](docs/ASSUMPTIONS.md).
