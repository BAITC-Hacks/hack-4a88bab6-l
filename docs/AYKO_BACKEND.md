# Отдельный backend ayko и HR-dashboard

Проект команды HackAlem AI: **Кейс 1 — Career Quest**, платформа геймификации жизненного цикла сотрудника. Текущий MVP помогает сравнить навыки сотрудника с карьерной целью, выбрать полезные активности и показать HR, где не хватает навыков или возможностей обучения.

Эта инструкция описывает сохранённый backend из ветки ayko. Основное приложение команды с React запускается отдельно по [корневому README](../README.md). У этих приложений разные API, вход и SQLite-базы; данные между ними автоматически не синхронизируются. В этом режиме профили доступны через API и в окне HR-dashboard.

## Что уже работает

| Функция | Реализация |
|---|---|
| Профиль и карьерная траектория | Роль, грейд, цель, hard/soft skills, текущие и целевые уровни, история, доступные следующие шаги |
| AI-рекомендации | OpenAI выбирает до 3 активностей из рассчитанных backend кандидатов; возвращаются названия и описания событий |
| Объяснения | Сервер требует минимум 3 разных фактора: грейд, skill gap, история участия, требования целевой роли |
| Обновление прогресса | Отметка выполнения сохраняется в SQLite; текущие навыки и доступные шаги пересчитываются |
| HR-view | KPI, разрывы навыков, heatmap подразделений, причины отсутствия следующего шага, статистика участия и фильтры |
| Импорт данных | Дополнительные сотрудники и история загружаются в формате стартового датасета с валидацией |

**Стек:** Python, FastAPI, Pydantic, SQLite, OpenAI Python SDK. HR-интерфейс — HTML/CSS/JavaScript, который отдаёт FastAPI. Node.js и отдельная установка SQLite для этого MVP не нужны.

## Быстрый запуск на Windows / PowerShell

Все команды выполняются **из корня репозитория в одном терминале**. Локальная проверка выполнена на Python 3.14. Если сервер уже работает, сначала остановите его через `Ctrl+C`.

### 1. Создайте окружение и установите зависимости

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-ayko.txt
```

При существующем `.venv` достаточно второй команды. Активация `Activate.ps1` не требуется.

### 2. Задайте пароль HR

Выполните первую команду, придумайте пароль, введите его и нажмите Enter. Символы скрыты.

```powershell
$hrPassword = Read-Host "Пароль HR для этого запуска" -AsSecureString
$env:HR_PASSWORD = [System.Net.NetworkCredential]::new('', $hrPassword).Password
```

Этот же пароль понадобится на странице HR. Пароля по умолчанию нет. Команды работают и при запрете запуска `.ps1` в PowerShell.

### 3. При необходимости подключите OpenAI

HR-аналитика, профили и пересчёт навыков работают без OpenAI. Для генерации AI-рекомендаций перед запуском сервера задайте API-ключ своего проекта:

```powershell
$apiKeyInput = Read-Host "OpenAI API key" -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $apiKeyInput).Password
```

Ключ хранится в окружении текущего процесса; не добавляйте его в код или Git. Модель можно выбрать переменной `OPENAI_MODEL`: используйте доступную вашему API-проекту модель с поддержкой Responses API и Structured Outputs. Текущее значение по умолчанию в коде — `gpt-6-astra`; доступность модели зависит от API-проекта.

### 4. Запустите сервер

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.ayko_main:app --app-dir backend --port 8001 --reload
```

После `Application startup complete` откройте:

| Страница | Адрес |
|---|---|
| HR-dashboard | [http://127.0.0.1:8001/hr](http://127.0.0.1:8001/hr) |
| Swagger: описание и вызов API | [http://127.0.0.1:8001/docs](http://127.0.0.1:8001/docs) |
| Статус загрузки датасета | [http://127.0.0.1:8001/api/health](http://127.0.0.1:8001/api/health) |

На `/hr` введите пароль из шага 2. Для вызова HR API в Swagger можно сначала войти на `/hr` в том же браузере и на том же адресе `127.0.0.1`, либо вызвать `POST /api/hr/login` с `{"password":"ваш пароль"}`. Браузер сохранит сессию в cookie. Внешний клиент тоже должен сохранять и передавать эту cookie.

Если запуск скриптов разрешён, есть сокращённый вариант: `.\backend\start_hr.ps1`. Он запрашивает пароль HR и запускает тот же backend. Переменные окружения нужно задавать до запуска сервера; после перезапуска терминала они задаются заново.

## Как показать проект

1. В Swagger вызовите `GET /api/employees` и выберите `employee_id`.
2. Откройте `GET /api/employees/{employee_id}`: профиль, цель, навыки, история и `next_steps`.
3. Вызовите `GET /api/employees/{employee_id}/recommendations`: до 3 курсов с объяснениями. Нужен настроенный OpenAI API. При отсутствии полезных кандидатов возвращается пустой список без обращения к модели.
4. Выполните `POST /api/employees/{employee_id}/activities/{event_id}/complete`, затем снова получите профиль: уровни навыков и доступные шаги будут пересчитаны. Повторная отметка неповторяемой активности вернёт `409`.
5. На `/hr` проверьте KPI, разрывы, причины отсутствия шага и участие в активностях. Клик по сотруднику открывает профиль с карьерной траекторией. Фильтры меняют все разделы согласованно.

HR-страница обновляет данные каждые 30 секунд, при возвращении на вкладку и кнопкой «Обновить». Отдельно показаны добровольные и обязательные активности. Фильтры MVP: подразделение, текущая роль, текущий грейд, сотрудники с критическими разрывами.

## Основные API-маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Статус датасета |
| GET | `/api/employees` | Список готовых профилей |
| GET | `/api/employees/{employee_id}` | Профиль, навыки, история, полезные следующие шаги |
| GET | `/api/employees/{employee_id}/recommendation-context` | Подготовленные данные для модуля рекомендаций; без вызова OpenAI |
| GET | `/api/employees/{employee_id}/recommendations` | Результат выбора OpenAI с объяснениями и данными событий |
| POST | `/api/employees/{employee_id}/activities/{event_id}/complete` | Сохранить выполнение и пересчитать навыки |
| POST | `/api/hr/login` | Вход HR по `HR_PASSWORD` |
| GET | `/api/hr/session` | Проверить HR-сессию |
| POST | `/api/hr/logout` | Завершить HR-сессию |
| GET | `/api/hr/summary` | Все HR-агрегаты; требуется HR-сессия |
| POST | `/api/data/import` | Импорт дополнительных данных |

Ответ рекомендаций сохраняет `event_id` для отметки выполнения, а в `event` возвращает название, описание, тип, формат, длительность и даты. HR-summary принимает `department`, `role`, `grade`, `critical_only`. Точный контракт, поля и примеры: [backend/README.md](../backend/README.md).

## Как считаются навыки и рекомендации

- Условное «сегодня» датасета — **2026-10-01**. История стартового набора: **2024-10-01 — 2026-09-30**. Все данные синтетические.
- Цель берётся из `career_goal`. Если её нет, выбирается следующий грейд текущей роли. У Lead без цели автоматический переход не определяется.
- Навыки в исходном профиле соответствуют `last_review_date`. Поверх них применяются только завершённые после этой даты активности. Учитываются `gain` и `max_level`; уже более высокий уровень не уменьшается.
- Разрыв: `max(0, target_level - effective_current_level)`. Отсутствующий навык считается уровнем 0.
- Единая функция `recommendation_candidates()` используется для профиля, контекста OpenAI, проверки ответа модели и HR. Кандидат должен уменьшать хотя бы один целевой разрыв, соответствовать текущей роли/грейду, prerequisites и расписанию.
- Обязательные события исключены из рекомендаций. Пройденные события не предлагаются повторно, кроме `EV_036`. Для `self_paced` будущая сессия не требуется.
- «Без полезного шага» — сотрудники с целью и разрывами, но без полезного доступного события. «Без карьерной цели» — отдельная группа. Эти списки рассчитываются без OpenAI.

Контрольные показатели **для исходного датасета и пустой SQLite-базы**:

| Показатель | Значение |
|---|---:|
| Сотрудников | 200 |
| С определённой целью | 190 |
| С критическим разрывом | 187 |
| Без полезного следующего шага | 30 |
| Без карьерной цели | 10 |
| Завершение добровольных активностей | 1044 / 1503 = 69,46% |

Completion rate: `completed / (completed + dropped + no_show + declined)`. `in_progress` и `overdue` в знаменатель не входят. После импорта или новых выполнений показатели могут отличаться от контрольных.

## Хранение, импорт и настройки

SQLite создаётся автоматически в `backend/data/career_quest.sqlite3`. Сохранённые отметки выполнения переживают перезапуск. Исходные JSON/CSV при выполнении активности не переписываются.

`POST /api/data/import` принимает четыре multipart-поля: `employees_file`, `events_file`, `skills_file`, `history_file`. Схемы соответствуют стартовому набору. Новые записи добавляются, совпадающие по ID и содержимому пропускаются, конфликтующие записи отклоняются. **Импортированный набор пока хранится в памяти и теряется при перезапуске сервера.**

| Переменная | Для чего |
|---|---|
| `HR_PASSWORD` | Пароль единственного HR-аккаунта демо; нужен для входа |
| `OPENAI_API_KEY` | Ключ для AI-рекомендаций |
| `OPENAI_MODEL` | Модель рекомендаций; по умолчанию в коде `gpt-6-astra` |
| `DATASET_DIR` | Папка датасета; по умолчанию `career_quest_dataset/` |
| `DATABASE_PATH` | Путь SQLite; по умолчанию `backend/data/career_quest.sqlite3` |

Текущие ограничения MVP:

- HR-сессии живут до 8 часов и сбрасываются при перезапуске или автоматическом reload. Предусмотрен один серверный процесс.
- HR-аналитика защищена сессией; остальные employee/import endpoints пока без авторизации сотрудника. Готовая HR-страница работает с API на том же origin; отдельный frontend потребует согласования CORS и передачи cookie.
- Рекомендации не сохраняются в отдельную таблицу: каждый вызов с полезными кандидатами делает новый запрос к OpenAI. Проверяются формат ответа, разные факторы, уникальность и допустимость выбранных событий; фактическое качество объяснений зависит от модели.
- Автоматические проверки не отправляют запросы OpenAI и не подтверждают доступность ключа, выбранной модели или баланса API.

## Проверки

Из корня репозитория:

```powershell
$env:PYTHONPATH = "backend"
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
```

Сейчас 9 проверок: контрольные HR-значения, фильтры и знаменатели, полезные кандидаты и расписание, причины блокировки, разграничение доступа, пересчёт после completion и импорта, отклонение неподходящего ответа модели. Используются временные SQLite-базы; рабочие данные не меняются.

## Частые ошибки запуска

| Ошибка | Что сделать |
|---|---|
| `running scripts is disabled` | Используйте команды быстрого запуска выше через `.venv\Scripts\python.exe`; запуск `.ps1` и активация окружения не обязательны |
| `No module named 'openai'` | Установите `backend/requirements-ayko.txt` именно через `.venv\Scripts\python.exe -m pip` |
| `503 HR-вход не настроен` | Задайте `HR_PASSWORD` в том же терминале и перезапустите сервер |
| `401 Unauthorized` в HR API | Войдите через `/hr` или `/api/hr/login`; после reload войдите заново |
| `503 Не задан OPENAI_API_KEY` | Задайте ключ до запуска сервера и перезапустите его |
| `502` при рекомендациях | Проверьте доступ API-проекта к модели, квоту/баланс и соединение; код также возвращает 502 при ответе неверного формата |
| Порт `8001` занят | Остановите предыдущий сервер через `Ctrl+C` |
