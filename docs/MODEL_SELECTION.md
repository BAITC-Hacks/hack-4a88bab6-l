# Выбор модели для рекомендаций

## Текущая конфигурация

`OPENAI_MODEL=gpt-4.1-mini` остаётся значением по умолчанию из полного задания Career Quest. Модель можно сменить через серверный `.env`, без изменения frontend. Исходные факты, допуск к мероприятиям и численный прирост вычисляет backend; модель выбирает и обосновывает 1–3 шага среди допустимых кандидатов. При ошибке или превышении времени виден источник `fallback`, а не мнимый ответ AI.

Официальная документация OpenAI, просмотренная для текущего выбора:

| Модель | Официальная страница | Состояние проверки в приложении |
|---|---|---|
| `gpt-4.1-mini` | [GPT-4.1 Mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) | Значение по умолчанию; ранний вызов завершился timeout примерно через 9,19 с при лимите 8 с. Позднее отдельный live-check дал проверенный ответ за 5,79 с. |
| `gpt-5.6-luna` | [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) | Один live-вызов завершился timeout примерно через 8,13 с при лимите 8 с. |
| `gpt-5.6-terra` | [GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra) | Страница изучена; live-вызов в текущей проверке не выполнен. |

Отдельный `GET /v1/models` OpenAI вернул HTTP 200 примерно за 1,08 с. Это подтверждает работоспособность ключа и сетевого доступа к этому endpoint в той проверке. Это не подтверждает успешное формирование рекомендации, доступность каждой конкретной модели или соблюдение целевого времени для полного запроса.

Позднее повторный live-запрос генерации на локальном сервере (`localhost:8012`) вернул `source=ai` и три события: `EV_005`, `EV_040`, `EV_036`. До этого тот же сценарий показывал `fallback`. Это подтверждает, что реальный путь модели хотя бы один раз завершился проверенным ответом; точная задержка успешного вызова не была измерена. Идентификаторы событий отражают только этот прогон, а не правило для конкретного сотрудника.

На текущем коде отдельная команда `.venv\Scripts\python.exe scripts/live_openai_check.py --employee E0005` вернула `validated_ai` для `gpt-4.1-mini` за 5,79 с: `EV_040`, `EV_036`, проверены все факторы объяснения. Предыдущая попытка этой команды завершилась `ValueError` за 4,38 с; ответ с ошибкой в UI должен переводить подбор на явно отмеченный `fallback`. Скрипт делает оплачиваемый вызов и не меняет сохранённые рекомендации. Один успешный прогон уложился в ориентир 10 с для AI, но не измеряет задержку полного UI-пути и не доказывает стабильное выполнение ориентира.

Два завершившихся timeout запроса и последующие успешные ответы не дают основания назвать какую-либо модель лучшей по скорости, качеству или цене. Разница между 9,19 и 8,13 с включает накладные расходы и обрыв по лимиту; полезный ответ ни в одном из этих двух опытов не получен. До выбора альтернативы нужны повторные запросы на одинаковом фактическом контексте, проверка валидности `event_id`/`evidence_ids`, доли успешных ответов, общего времени до UI, качества ранжирования и расхода токенов. Лимит ТЗ для AI-рекомендации — до 10 с на полный пользовательский путь.

Live-проверки требуют локального серверного `OPENAI_API_KEY`. Ключ не фиксируется в этом документе, репозитории, браузере или логах. Автоматические тесты с mock проверяют логику приложения, но не скорость и доступность OpenAI API.
